The judging lens

Five criteria. One clear mission.

Explore the value, the working evidence, and the next proof point for each criterion. Weights total 100%.

30% WEIGHT · REQUIRED · 0–100 PTS

Give attention back to the mission.

Reduce the effort of reconstructing an engineering request: what happened, who owns it, what was approved, and what is still waiting.

Working evidence. A shared record combines condition, attachments, assigned engineer, status, comments, and approval history.

Deckplate value. Designed to reduce status chasing and repeated explanations across shop, engineer, and supervisor handoffs.

Prove in a pilot. Measure hands-on minutes per request, status inquiries, and rework against the current process. Watchstander burden and hours saved have not yet been measured.

20% WEIGHT · REQUIRED · 0–100 PTS

A small integration footprint. A defined path afloat.

A reusable web component can sit inside an existing host application. Container packaging provides a starting point for a controlled local deployment.

Working evidence. Embeddable Vue component, documented host/API contracts, and Docker packaging for the demo.

DDIL boundary. The prototype needs a reachable API and has no offline queue or synchronization. Local hosting alone does not establish disconnected, intermittent, or limited-bandwidth readiness.

Next gate. Add durable local storage, offline identity policy, queued changes and conflict handling; test link loss, recovery, and restart afloat. Fielding time is not yet validated.

20% WEIGHT · REQUIRED · 0–100 PTS

Reuse the workspace. Adapt the mission context.

The same request-to-closeout pattern could support more facilities and maintenance communities without rebuilding the entire user experience.

Working evidence. Isolated component instances, host-supplied tokens, documented APIs, and cross-TRF read/review permissions.

Expansion opportunity. Validate common handoffs across ship classes and ratings; adapt forms, authority rules, and data connectors to each operational domain.

Next gate. Replace process-local state with shared persistence and production identity, then load-test and validate access boundaries. Current demo deployment is one replica; fleet-wide use is not proven.

15% WEIGHT · REQUIRED · 0–100 PTS

Stop rebuilding the same context.

Bring job information, reusable engineering content, and decision history into the workflow so each handoff starts with the record already in view.

Working evidence. Synthetic JCN/LDS lookup, approved-template insertion, copy-forward revisions, attachments, and PDF export.

Friction removed. Reduce opportunities for retyping job details, searching for prior rationale, and assembling a separate closeout packet.

Prove in a pilot. Connect an authoritative job source and compare duplicate field entry, incomplete submissions, and time spent assembling records. Historical matching is a deterministic mock, not production AI.

15% WEIGHT · REQUIRED · 0–100 PTS

Simple for the Sailor. Accountable by design.

The innovation is the connected experience: a clear next action, preserved engineering rationale, and a traceable record across the entire lifecycle.

Working evidence. Role-aware actions backed by API authorization, identity-derived demo signatures, frozen revision history, and printable records.

Technical execution. Vue 3 + TypeScript and an ASP.NET Core API, with unit, component, backend, and browser workflow test coverage in the repository.

Judge it live. Follow the role handoff, try an unauthorized action, inspect a revision, and export the record. Validate usability with Sailors and production signing requirements before operational use.

DEMONSTRATED IN THE PROTOTYPE

The complete engineering handoff

  • Request, assignment, technical resolution, approvals, shop disposition, and division closeout.
  • Attachments, comments, signatures, revision history, and a downloadable PDF record.
  • Reusable component and API contracts for integration into a host application.
PROPOSED FIELDING GATES

Earn the right to scale

  • Pilot: pair with a facility and Sailor users; establish baseline effort and success criteria.
  • Harden: durable records and audit, production identity/signing, approved forms, and live data integration.
  • Prove afloat: DDIL recovery, security authorization, supportability, and multi-domain fit before wider rollout.

The ask: a pilot partner and a real workflow.

Provide engineering and shop users, access to approved integration owners, and a bounded trial. Measure whether fewer handoff delays and less administrative effort return time to the deckplate.
